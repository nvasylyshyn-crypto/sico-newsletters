## Project overview

This is a Next.js app that archives and serves SICO Bank's HTML email newsletters. The
app itself is a thin routing/wrapper layer — the actual content is ~1000 static
HTML/CSS/JS/image files under `public/`, each a self-contained legacy newsletter (originally
generated by an external tool and localized into this repo). The app is deployed to
Cloudflare Workers via OpenNext and mounted under the `/newsletters` path of a larger
Webflow-hosted site (see `webflow.json`'s `mountPath`).

## Commands

- `npm run dev` — start the Next.js dev server
- `npm run build` — production build
- `npm run start` — run the production build
- `node scripts/<script>.mjs` — run any maintenance script directly (no test runner or lint
  script is configured in this repo)

## Architecture

### Two ways a newsletter gets served

1. **Dynamic route**: [src/app/[newsletter]/route.ts](src/app/%5Bnewsletter%5D/route.ts)
   maps a slug (e.g. `1h25`) to a source file via the `ENTRY_FILES` map, reads it from
   `public/`, injects/rewrites a `<base href="/newsletters/<slug>/">` tag, and returns it.
2. **Static entry pages**: `scripts/generate-entry-pages.mjs` pre-generates flat files like
   `public/1h25.html` from the same source files (its own `ENTRIES` list mirrors
   `ENTRY_FILES`), with the same base-href injection done at generation time instead of at
   request time. [src/app/page.tsx](src/app/page.tsx) links to these flat `.html` files.

Both mechanisms exist for the same set of newsletters and both rely on injecting a
`<base>` tag so the newsletter's own relative asset paths (css/js/img/fonts) resolve
correctly once served under `/newsletters/<slug>/`. **When adding a new newsletter
archive, update both `ENTRY_FILES` in `route.ts` and `ENTRIES` in
`generate-entry-pages.mjs` — they must stay in sync.**

### `public/` structure

Each newsletter lives in its own top-level directory (`1h2022/`, `1h2025/`, `1h24/`,
`1h25/`, `1q2023/`, `2h2020/`, `2h2022/`, `2h23/`, `MailShot/`), containing the original
newsletter's HTML entry file plus its own `css/`, `fonts/`, `img/`, and sometimes a nested
`Themes/Default/...` directory tree (a leftover from the original hosting platform).
`public/assets/external/` holds third-party assets (jQuery, Bootstrap, Google Fonts, S3
images) that were downloaded and localized by the migration scripts below.

### Migration/maintenance scripts (`scripts/`)

These were written to localize originally externally-hosted newsletters into this repo and
to keep their internal links consistent. Run them from the repo root with `node`:

- `localize-assets.mjs` / `localize-annual-report.mjs` — scan `public/**/*.{html,css,js}`
  for hardcoded external URLs (S3 buckets, CDNs, sicobank.com) matching a fixed pattern
  list, download each asset into `public/assets/external/`, and rewrite all references to
  the local path.
- `check-links.mjs` — walks `public/` and reports any relative `href`/`src` that doesn't
  resolve to an existing file (does not fix anything).
- `repair-broken-links.mjs` / `normalize-archive-links.mjs` /
  `finalize-archive-localization.mjs` — targeted link-rewriting passes for cleaning up
  broken/inconsistent relative paths found by `check-links.mjs`.
- `generate-entry-pages.mjs` — see "Two ways a newsletter gets served" above.

There's no automated pipeline chaining these — they're run manually, one-off, when
onboarding a new archived newsletter or fixing links in an existing one.

### Deployment

- `next.config.ts` sets `basePath: '/newsletters'` and `images.unoptimized: true` (static
  legacy HTML doesn't use `next/image`).
- `wrangler.json` + `open-next.config.ts` configure the Cloudflare Workers deployment via
  `@opennextjs/cloudflare`.
- `webflow.json` records that this app is mounted at `/newsletters` inside a Webflow site.
